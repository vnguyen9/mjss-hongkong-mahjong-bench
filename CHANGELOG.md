# Changelog

## 1.1.0 (2026-11-21)

* Added “Matches against outside bots” in `RESULTS.md`, with a summary in the README.

A bot could rebuild the private wall from `rng_seed`. This release fixes that. Every decision carried `rng_seed = splitmix64(deal seed, arrangement, seq)` and every game a `game_id` that named the deal number and arrangement. A bot that inverted the seed (by search, when the deck was a start and a count) knew the deal seed, and the bench's own public shuffle then gave it the wall and every hidden hand. The fair-play check used `game_id` `"fairplay"`, so a bot could tell it was being checked, and bots inherited the runner's environment (the private deck's path included) and lived across games. No third-party bot has played the private deck, so no private row was affected by an outside bot. The baselines and the hosted bot were re-scored under the new scheme on a new private deck, on another machine (see the re-scoring entry below).

* `rng_seed` is now the low 31 bits of an HMAC-SHA256 under a run key, over the table, deal number, arrangement and decision number. The deal's seed is not an input. A private-deck run draws a 32-byte key from the operating system; it lives only in the bench's own processes and is never written to a result, a log or the environment, nor sent to a bot. A public-deck run uses a fixed public key (`sha256("hkbench-public-rng-v2")`), so public runs still repeat exactly and their logs reproduce. The fair-play check uses the run's key, so it is not different from a game. The old `runner.decision_seed` is gone.
* `game_id` is now 32 hex digits, an HMAC of the same inputs under the run key. It names no deal, arrangement or check.
* A bot that is a program is started afresh for every seat of every game and stopped when the game ends (it used to live for a whole run, and one process served both seats of a team in a head-to-head). The fair-play check does the same for every ask. A program bot's environment is `PATH`, `LANG`, `LC_*` and `SYSTEMROOT`, plus a new empty directory as `HOME`, `TMPDIR`, `TEMP`, `TMP` and working directory; `--bot-env NAME` (score, h2h, fairplay) hands over named variables; `HKBENCH_*` is never passed. Cost, measured on a busy machine (the Python example, 120 games): one worker 10 to 12 games a second before and 7 to 9 after, four workers 21 to 26 before and 19 to 25 after; its fair-play check takes about 19 s instead of 2 s (it plays the bot and waits out the replay pauses).
* The second review commit added these fixes. The fair-play check plays the bot itself, in real games against the field, on deals drawn from a per-check secret (32 random bytes; never a known range or a public deal; `hkbench fairplay --debug-fixed-check` repeats the deals and is documented as recognisable). The earlier-messages replay now follows the bot's own moves, not the reference bots'; the answer it gives to each replayed message must match the move it played, or it counts as a changed decision. Each bot process has its own new empty directory as `HOME`, `TMPDIR`, `TEMP`, `TMP` and (without `--cwd`) its working directory, deleted afterwards; a relative script path in the command is made absolute first. A bot starts in its own process group (a new session; `CREATE_NEW_PROCESS_GROUP` and `taskkill /T /F` on Windows) and the whole group is killed when the game ends, with a one-second grace after `bye` and bounded pipe cleanup, so a descendant can neither outlive the game nor hang the run. Private seeds outside [0, 2^64) are refused by the loader and never made by the generator (`public start + 2^64` used to pass as private and deal a public wall). `--private-seeds=PATH` and the path inside any other word are hidden in the recorded command.
* The third review commit added these fixes. The fair-play check seats the bot at every position against the dealer (dealer and wind step every four games, the checked seat every game), where it was always dealer, so a bot honest only as dealer used to pass. The replay waits the pauses the live game had between each answer and the next message (capped at 2 s). A request that fails validation (an unmatched quote, an `HKBENCH_*` override, a program that cannot start) no longer leaves a scratch directory behind. Scratch directories sit under one parent per run process, mode 0700, removed with the last one. New `--sandbox CMD` (score, h2h, fairplay): a command prefix in front of every bot launch, one sandbox per bot process, stopped with SIGTERM then SIGKILL on the wrapper; the bench leaves the environment and directories to it. A private-deck run of a program bot without it is refused unless `--native-unsafe` (warning printed). Results and log headers record `"isolation": "sandbox"` or `"native"`; a private run of a program bot without a sandbox is never tagged verified. Docs: a Docker recipe in `SUBMITTING.md`, and what native mode cannot stop, `game_over` included.
* **macOS sandbox (fourth commit).** `scripts/sandbox/macos.sh`, for `--sandbox`: `sandbox-exec` with a profile made per launch (no network, no fork, no POSIX shared memory or Mach registration, writes only to a new scratch directory under a shared 0700 parent that is removed on exit and on SIGTERM, other launches' directories and every `--deny-read` path unreadable). Measured on the re-scoring Mac: the system Python and the hosted torch bot both start and play under it, and the hosted bot scores the same as natively over 8 games; reads elsewhere on disk are still allowed, so the deck must be passed with `--deny-read`. Tests run the probes on macOS and skip elsewhere.
* Every result and log header records `"rng_scheme": "hmac-sha256-v2"`; a file without the field is `splitmix-v1` (the leaderboard rows carry it).
* **Re-scored (fifth commit).** Every row in `results/` and on the board was run again under 1.1.0 on 20 and 21 November 2026: on each table, `random`, `deficiency`, `ukeire`, `faan_aware` and the Python example at 2,000 deals, `shallow_search` at 400, `Fu-2.3M-HKMA-1` at 2,000, and the three 300-deal head-to-heads, on the public deals and on a new private deck of 10,000 independent random seeds made with `scripts/make_private_deck.py`. The Python example and `Fu-2.3M-HKMA-1` ran under `scripts/sandbox/macos.sh` with the deck unreadable. All 51 runs passed the fair-play check with no excess faults, every private run is tagged verified, and all 283,800 public games replay with 0 mismatches. The 1.0.0 files (`splitmix-v1`) were removed from `results/` and stay in the history. Public rows moved by up to 0.4 points a hand for the baselines and 0.6 for `Fu-2.3M-HKMA-1`; `Fu-2.3M-HKMA-1` is still first on every table and deck. `SUBMITTING.md` and the sandbox script now say that under `--sandbox` a bot's script must be given by absolute path, since the bot starts in an empty directory.
* New `scripts/make_private_deck.py --count N --out PATH`: independent random 64-bit seeds from `secrets`, none inside any table's public range, written as `{"seeds": [...]}` with mode 0600, and it will not overwrite a file. A private deck in the old `{"start": S, "count": N}` form is refused (one seed gave every deal); a list of 10 or more consecutive seeds is read with a warning.
* Tests: `tests/test_seed_hole.py` (the old inversion recovers nothing from a keyed run, public runs repeat, private streams follow the key, game ids are opaque, a bot's process is new each game and sees no `HKBENCH_*`, the key is in no result or log, the deck generator), and the training-log test for the key. The fair-play tests' leak variable is now `CHEAT_TEST_LEAK`, passed with `bot_env`.

This does not stop a bot that can read the bench's files or memory as the same operating-system user (it could read the deck file). Run submitted bots in a container that holds no deck.

Version 1.1.0 also includes the following changes:

* `--training-log` (for `score` and `h2h`, off by default): a won game's log line also carries the winner's `melds`, `concealed` tiles (the winning tile included), `winning_tile`, `flowers` and `winner_draws`, for training. With it off the logs are byte for byte what they were; on a private deck it does nothing; the `game_over` message to bots is unchanged. A log written with it still replays with `verify-log`.
* New table `hk-chicken-v1` (chicken hand): `hk-hkma-v1` with exactly one change, `win.minimum_faan: 0`. A complete hand with no scoring pattern wins and pays the 0-faan row; faan still score and pay as usual (cap 10, no flower faan, no Seven Pairs, the discarder pays all). It is not a table where every win pays the same. It uses the same three-bot field with unchanged pins. It has its own rules hash, public deal range (3,000,000 to 3,099,999) and engine fingerprint (300 deals, 42 hands, 198 wins). The engine needed no change: the win action is offered whenever a hand is complete and reaches the table's minimum. The pins and fingerprints of `hk-hkma-v1` and `hk-house-v1` did not move, and a test pins them to their old values.
* Baseline rows on `hk-chicken-v1`, public and private deals: random, deficiency, ukeire, faan_aware and the Python example at 2,000 deals, shallow_search at 400, and 300-deal head-to-heads (five bots on public deals; six with the hosted bot on public and private deals). All 94,600 public games replay with 0 mismatches; a 60-deal row is identical on Python 3.9 (where the rows ran) and 3.11.
* The hosted bot `Fu-2.3M-HKMA-1` is scored on `hk-chicken-v1`, public and private deals and in the head-to-heads. It is told the rules the way the app's Beginner table tells it (no-faan bit on, win-out inputs under this table's rules); the setting was chosen once from that rule and the other was not run. Its hash differs from its other rows because the hash covers the wrapper.
* `RULES.md` has a section for the new table, and the leaderboard lists tables in release order.
* The hosted bot is now named `Fu-2.3M-HKMA-1`. The name gives its family, size (2.3M parameters), the rules it trained on, and version. Its result files, logs and head-to-head entries are renamed; no game, score or hash changed.

## 1.0.0 (2026-11-16)

First release.

* Rules engine and scorer, adapted for the bench with private development artifacts excluded.
* Table `hk-hkma-v1` (HKMA Classical): rules, a frozen field of three reference bots (`faan_aware`, `ukeire`, `deficiency`) pinned by source hash, a public deal range, and an engine fingerprint of 300 deals and 42 hands.
* Table `hk-house-v1` (House): flowers score, limit hands are graded, cap 13, and Seven Pairs is a hand (4 faan, seven different pairs, concealed only, stacking with flushes, Self-Drawn, Closed Hand and flowers; All Honours by Seven Pairs is a limit hand). Same three-bot field, its own pins and fingerprint, and the same baseline rows as HKMA.
* Duplicate scoring, head-to-head matches with Bradley-Terry ranks and bootstrap intervals, deal-clustered intervals, the hidden-tile fair-play check, public and private deal decks, result and log files.
* Protocol `hkbench-1`, with example bots in Python and JavaScript.
* Static leaderboard (`site/`) with Bots, LLMs and Humans tracks.
* Baseline rows on both tables, public deals (unverified): random, deficiency, ukeire and faan_aware and the Python example bot at 2,000 deals each, shallow_search at 400, and a 300-deal head-to-head of five of them, on each table. They reproduce byte for byte on Python 3.9 and 3.11.

Changes from the source engine:

* Fixed: a Bless of Heaven hand (the dealer wins on the first draw) was accepted but scored as an ordinary hand. It now scores 10 faan on HKMA and 13 on House.
* Fixed: a settlement that does not sum to zero stops the run. It used to be repaired quietly.
* Changed: the deal shuffle is the bench's own SplitMix64 Fisher-Yates, so a seed is the same deal on every Python version.
* Fixed: opening flowers are replaced dealer first, in turn order, each seat until it holds none. The engine used to start at seat 0 whatever the dealer. This changes the dealt hands whenever the dealer is not seat 0 and a flower is dealt.
* Fixed: a limit hand dropped Self-Drawn, Last Tile from the Wall, Robbing a Kong and the kong items. They now count, then the cap applies. No money changes on `hk-hkma-v1` (its limits already sit at the cap); on House (cap 13) a self-drawn 10-faan limit is 11. This changed the `faan_aware` source, so the field pin and the engine fingerprint were re-made. The table is still v1: it had not been published.
* Added: Seven Pairs (`is_seven_pairs`, scored in `_score_seven_pairs`), played only where a table's rules file says `win.seven_pairs: true`. It competes with the ordinary reading of the same tiles on raw faan, so a hand that reaches the cap either way is named for the richer one. The HKMA table is unchanged by it: its engine fingerprint over 300 deals is the same before and after. The field's source hashes moved with the engine, so both tables' pins and fingerprints were made after it, and the baseline rows were rerun.
* Changed: on `hk-hkma-v1` the seven and eight flower instant wins are off, because the rulebook has no flower win.
* Changed: the reference bots read the same seat view an outside bot gets, and draw their randomness from the decision's `rng_seed`. `wait_aware`, which reads other players' hidden hands, is not included.
